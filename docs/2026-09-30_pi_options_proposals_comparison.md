## 0. 结论先行

1. **方向高度一致，Codex v0.2 更适合作为实施基线。** 两份方案的产品骨架相同：
   - 一个 Pi package（Skill + 薄 Extension + Python），行情来自 IBKR；
   - LLM 不做数值计算；意图写成结构化规格，由确定性程序落到真实合约，再做约束检查；
   - 本地定价用 QuantLib；不下单；以 Pi ≥ 0.99.1 为基线；由一个会话级 Python 进程持有唯一的 IB 连接。

   Codex v0.2 在三个方面明显更好：
   - **IBKR 字段语义更精确**：字段级的来源与时间、请求编号与回调编号的对应、持仓量的业务日期未知、数据类型以回调为准、结算方式可读而行权方式不可读。逐条核实全部成立（§5）。
   - **v1 范围更克制**：单腿加四种同到期垂直价差；SVI 曲面、盈利概率（POP）、β 加权、跨期结构都设了加入条件。
   - **计算规则更严谨**：按用途分三条定价路径；情景的基准和冲击用同一个模型；IV 可识别性按价差衡量；约束检查有"未知"状态。本次实验 E14–E16 都支持它的立场。
2. **Claude v0.1 有四项内容是 v0.2 缺少、值得补进去的**：
   - **实测证据**：E11–E13 的精度、速度和美式偏差，以及本次的 E14–E16。v0.2 明确写了没有安装或验证任何定价库。
   - **LLM 期权 Agent 的前沿教训和评测方法**。LiveOption（2026-09）发现：Agent 的典型收益为负；去掉持仓状态后回撤约翻三倍；通过展期、加仓叠加杠杆。对应的评测方法是统计不交易率、被拒绝率、尾部分布，并做消融实验。v0.2 没有引用 LiveOption，验收只写了"真实模型岗位任务"（V28）。
   - **外部历史期权数据路线**：DoltHub 的实测覆盖，以及 ORATS、Cboe、ThetaData、Databento 的概况。v0.2 的 v1 已经包含标的 IV/HV 历史背景（Rank/Percentile）和自存的有限观测，但把完整回测"另行立项"，没有指出可用的外部历史期权数据来源。
   - **具体示例**：StrategySpec 的 YAML 样例、交易单字段、工具清单。v0.2 只有字段表。
3. **本次核查发现了双方都没提到的客户端事实**，它们直接影响 v0.2 最大的技术选择（官方 `ibapi`，而不是 ib_async）：
   - 官方 `ibapi` 10.50.2 采用 **GPL-3.0-or-later** 许可，精确锁定 `protobuf==5.29.5`，基于线程、没有 asyncio 接口。PyPI 上叫 `ibapi` 的包是 2020 年的 9.81.1，不能直接 `pip install`。
   - ib_async 自 2025-12 起没有新提交，可协商的最高客户端版本是 178（官方为 226），读不到 `settlementMethod`。

   这两组事实指向相反：前者给 v0.2 的选择增加了许可和安装成本，后者证明它选官方客户端的理由成立（能跟上新字段和协议）。v0.2 已把"官方发行来源、许可与安装"列为 OP0 待定项，并决定不随包再分发官方源码；本次核查给出了这几项的具体答案。结论是 v0.2 的选择在技术上站得住，OP0 需要据此写定许可决定和安装方式。另外，Qlib 包（A v2.1 用的是 ib_async）面临同样的维护风险。
4. **真正需要你拍板的分歧有五项**（§10）：
   - v1 是否包含"会话内自动研究"（v0.2 包含，v0.1 不包含）；
   - IB 客户端用官方 `ibapi` 还是 ib_async，两个包是否统一；
   - v1 的分析深度（v0.2 克制，v0.1 较宽）；
   - 交付格式（v0.2 用 Markdown，v0.1 用经过浏览器核验的离线 HTML）；
   - 历史研究路线（v0.2 另行立项，v0.1 分期引入）。
5. **Claude v0.1 有 10 处被证实的错误或不精确**（§6.1），包括"收盘后的分析一律标为 frozen""成交量必须用流式请求取得""行权方式取自合约详情""裸卖出都是无限风险"。这些点上 v0.2 的说法都是对的。

**本次新增的核查与实验**：

| 编号 | 验证什么 | 结果 | 影响 |
| --- | --- | --- | --- |
| S1 | 官方 Python 客户端 `ibapi` | 10.50.2（2026-09-29 发布）；GPL-3.0-or-later；锁定 `protobuf==5.29.5`；`MAX_CLIENT_VER=226`；能解析 `settlementMethod`；基于线程的 `EReader`；zip 可以直接下载 | 支持 v0.2 的选型理由，同时带来许可和安装成本 |
| S2 | PyPI 上的 `ibapi` | 只有 2020 年的 9.81.1 和 9.81.1.post1 | 依赖锁必须指向官方 zip（URL 加哈希），不能从 PyPI 解析 |
| S3 | ib_async 2.1.0 | BSD 许可；最高客户端版本 178；不解析 `settlementMethod`；最后一次提交在 2025-12-06 | v0.1 与 Qlib 包所选的客户端有停更和协议落后的风险 |
| E14 | "中间价对应的 IV"与"两侧 IV 的平均" | 中位差 0.003 个波动率点，最大 2.24 点（实值、低 vega 的合约） | v0.2 的说法正确，但大多数情况下影响很小 |

## 3. 共识

以下 17 项两份方案各自得出了相同结论，可以视为已定：

1. 一个 Pi package：Skill + 薄 Extension + Python 项目；不另建宿主、服务或交易系统。
2. 行情来自 IBKR 的 TWS/Gateway Socket API；首批是美股个股和 ETF 的标准期权。
3. IBKR 不提供已到期期权的历史，也不提供期权的日终（EOD）数据；不承诺基于 IBKR 的完整期权回测。
4. 行情线是共享的硬约束：与 TWS 界面共用，换 client ID 不会增加额度；先筛选再取报价；本包自设预算。
5. `snapshot=True` 只返回默认字段，约 11 秒后结束；需要附加字段时用有界的流式请求。
6. 实时希腊值需要期权和标的两份订阅；每个报价都要保存数据类型。
7. LLM 不做数值计算；意图写成结构化规格，由确定性解析器落到 conId（两份都引用了 OQL）。
8. 约束和风险检查由确定性代码完成；被拒绝的方案保留分析，但不生成"已合格"的草稿。
9. 标注 `executable:false`，不下单、不行权；WhatIf 默认关闭。
10. 本地美式定价以 QuantLib 为主，不自写通用的美式求解器。
11. IV 能否识别要单独判断，不能以"求解收敛"为准。
12. 持仓首版以文件导入为主，通过 API 读取需要另行授权。
13. Pi ≥ 0.99.1，使用 `outputSchema`/`structuredContent`、按需暴露等新的工具能力（v0.2 另外明确指出 `annotations` 不是安全边界）。
14. 由一个会话级 Python 进程持有唯一的 IB 连接（v0.1 称为 sidecar，v0.2 称为"行情与分析主进程"）。
15. 期权链数据不进入上下文，工具只返回摘要和引用。
16. 0DTE 与期货期权不进首版。
17. 结论必须标注数据时点、来源和假设；不构成投资建议。

## 8. 可实施性

### 8.1 v1 工作量构成（相对规模，判断）

| 能力块 | Claude v0.1 | Codex v0.2 |
| --- | --- | --- |
| 分发、环境、IB 连接 | 中（ib_async 现成） | 中到大（为官方客户端写异步适配与请求关联） |
| 链、报价、质量、view | 中 | 中 |
| 波动率分析 | 大（含 SVI 与四种 RV） | 中（离散观察点，一种 RV） |
| 定价与情景 | 中（两个引擎） | 中（一个引擎，但要求更严） |
| 策略解析、评估与约束 | 大（10 种以上模板） | 中（单腿加四种垂直价差） |
| 持仓风险 | 中（含 β 加权） | 中 |
| 会话内自动研究 | — | 大 |
| 研究（IV 指数） | 小到中 | — |
| 报告与核验 | 大（HTML 加浏览器核验） | 小（Markdown 加证据） |
| 验收 | 大（Agent 行为评测） | 大（28 个场景加 12 个探针） |

**结论**：v0.2 的 v1 在分析和报告上更小，但增加了自动研究和官方客户端适配这两块较大的工作；两者总量接近。按 v0.2 的范围推进，并按 §9 补上缺口，工作量可控。

### 8.2 外部依赖与风险

| 依赖 | 影响 |
| --- | --- |
| 行情订阅（期权加标的） | 决定是实时还是延迟数据，以及能否拿到希腊值；两份方案都要先确认你的订阅现状 |
| 行情线额度 | 自动研究需要常驻订阅，与 TWS 界面和 Qlib 包共用额度 |
| 官方客户端的协议演进 | 官方客户端能跟上，ib_async 目前落后 48 个客户端版本 |
| 许可 | 选官方客户端就会引入 GPL；个人使用不受影响，公开发布需要处理 |
| 事件数据 | 财报日期要有来源（WSH 研究订阅或用户提供），否则相关约束只能是 UNKNOWN |

## 9. 融合建议

1. **以 Codex v0.2 及其矩阵作为唯一实施规范**：字段语义和计算归属以矩阵为准；v0.1 转为历史参考。
2. **从 v0.1 补入以下内容**：
   - E11–E16 的脚本，作为 OP0 的数值测试向量；
   - LiveOption 的教训：组合层面的杠杆与最大亏损约束（X-4）；行为评测，包括不交易率、被拒绝率、尾部分布和消融（X-3）；
   - StrategySpec 的 YAML 样例和交易单字段（X-8）；
   - 历史数据路线：v1 保持 v0.2 已有的标的 IV/HV 历史背景与自存观测；规则检验类研究、外部历史期权数据（R3）以及 DoltHub 实测覆盖，作为回测立项的输入（X-5）。
3. **补写新的事实**：官方客户端的许可、protobuf 锁定、安装来源和线程模型（X-1）；与 Qlib 包的 clientId 与行情线协调约定，以及版本差异（X-7、X-10）。
4. **从 v0.1 删除或修正**：§6.1 中的 C-1 到 C-10。
5. **跨包影响**：Qlib 包 A v2.1 使用 ib_async，存在同样的停更和协议落后风险（S3）。另外，官方客户端从服务端版本 220 起有 `MARKET_DATA_VOLUMES_IN_SHARES`，而 ib_async 最高只协商到 178，成交量单位的语义可能因客户端版本而不同，需要在 Qlib 包的 C12（IBKR 真实历史回归）中实测。建议两个包对客户端做一次统一决定。
